## Sobre commitear y archivar — lo aprendido a los golpes

El circuito que funciona es: **commit del trabajo → archivar → commit del movimiento**. Dos commits, no
uno ni seis.

Ale intentó una vez commitear grupo por grupo para conservar los mensajes sugeridos, y le salieron seis
commits, dos de los cuales partieron un rename al medio y rompieron `git log --follow`. Eso ya está
arreglado —las mitades van juntas— pero la lección queda: **si el mensaje sugerido sale vacío, no es un
error a esquivar partiendo el commit**. Sale vacío porque la selección abarca varios cambios, y eso es
información: o está bien mezclado y escribís el mensaje a mano, o no debería estar mezclado.

Cuando varios changes tocan los mismos archivos de código —pasa siempre que trabajás dos seguidos—
**no se pueden separar**: Git stagea archivos enteros. Un commit mezclado con mensaje escrito a mano es
la respuesta correcta, no un problema.
